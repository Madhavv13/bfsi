# BFSI APT Intel: static site (Astro 7)

This is the public half of the project. Pages come from JSON written by the private pipeline
(`bfsi-intel export`). Do not hand-edit `src/content/groups/*.json`. Any change is
overwritten on the next export, and the build validates every file against the schema.

```bash
npm ci            # or `npm install` the first time, then commit package-lock.json
npm run dev       # http://localhost:4321
npm run build     # static output in dist/, then the Pagefind search index in dist/pagefind/
npm run preview   # serve dist/ (search only works on a build, not in dev)
```

## What it builds

* **`/`** lists the groups, ordered by tier.
* **`/groups/<slug>/`** shows, for each group:
  - name, aliases, nexus and BFSI rationale
  - the description, with references
  - a table with the columns **Attack Name | Description | Tactic | Technique**, linking to
    attack.mitre.org
  - provenance badges (*ATT&CK* / *Reviewed auto-map*)
  - a tactic and source filter, which is progressive enhancement (`public/scripts/tactic-filter.js`)
  - CSV and Navigator-layer downloads
* **`/techniques/`** lists every technique used on a group page, grouped by tactic.
  **`/techniques/<id>/`** shows the ATT&CK description, its sub-techniques, and every group's
  procedures for that technique. Built from `src/data/techniques.json` plus the group pages.
* **`/search/`** uses Pagefind. Only group and technique pages are indexed
  (`data-pagefind-body`). Aliases are weighted, so "BlueNoroff" finds APT38.
* **`/licenses/`** covers the MITRE notice and trademark, the CC BY 4.0 licence for original
  analysis, and the data-source terms.
* **Footer** carries MITRE's required copyright notice and the attribution disclaimer.
* **All data is rendered as escaped text.** There is no `set:html`.

## Content contract

There are two checks on the content:

* `schemas/group.schema.json` and `schemas/techniques.schema.json` are generated by the
  pipeline and copied here on every export. CI runs `ajv` against both before building.
* `src/content.config.ts` mirrors the same schema in Zod. A malformed file fails the build.

## Deploy (GitHub Pages)

1. Make this folder its own repository and push it to GitHub.
2. In the repo, set Settings → Pages → Source to **GitHub Actions**.
3. `.github/workflows/deploy.yml` builds with `withastro/action` and deploys with
   `actions/deploy-pages`.

It sets `SITE_URL` and `BASE_PATH` automatically for a project page
(`https://<user>.github.io/<repo>/`). For a `<user>.github.io` repo or a custom domain, set
`BASE_PATH: /`. For a custom domain, also add `public/CNAME`.

For "Open in ATT&CK Navigator" links, set `export.site_base_url` in the pipeline's
`settings.yaml` to the deployed URL. GitHub Pages serves the layer JSON with
`Access-Control-Allow-Origin: *`.

## Publishing flow

```
pipeline: bfsi-intel export  →  this repo: git add -A && git commit -m "data: export" && git push  →  Actions deploy
```

Committing and pushing is always a manual step.
